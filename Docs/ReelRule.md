# リール制御エディタ

制御（内部名）ごとに「狙う出目」を並べるだけで、全押し順・全押下位置の滑りテーブルを自動生成するエディタです。
当選役の引込と非成立役の回避は自動で行い、デザイナーは出目の出し分けだけを指定します。

- 画面: `UdonSlot > リール制御エディタ`
- 設定の保存先: `ReelDesignAsset`（`Create > UdonSlot > リール制御設計`、または画面の「新規」）
- 生成エンジン: `Editor/ReelRule/Core`（Unityに依存しない純C#）
- テスト: `Tests~/ReelRule`
- 出力: 既存の `ReelControlData`（基本テーブル＋停止位置の条件付きテーブル）。実機側の処理は変更しません。

## 使い方

1. 上部の「機種」に `ReelOutputController`（派生クラス可）を指定します。配列・有効ライン・配当表・抽選表はここから読みます。
2. 「設計」の「新規」でアセットを作ります。抽選表の全フラグと同名の制御が入った状態で始まります。
3. 「リール画像」にリールテクスチャを指定すると、図柄が画像で表示されます（3リールを横に並べ、各リールの1番を上にした画像）。
4. 「制御方式」（ボーナス優先／小役優先）と「最大滑り」を決めます。最大滑りの初期値は機種の `maxSlipCount` です。
5. ②「出目」で基本目・リーチ目を作り、①「制御」で制御ごとに狙う出目を並べます。
6. 変更するたびに裏で再計算されます（上部に「計算済み」と出れば最新）。
7. 「ベイク」で、機種の `ReelControl` に登録された内部名と同じ名前の制御を、対応する `ReelControlData` に書き込みます。その後シーンを保存します。

「レポート保存」は結果を Markdown に書き出します。

## ① 制御

1つの制御 = **内部名**（`ReelOutputController.GetReelControlFlagName()` が返す検索名）＋ **抽選フラグ**。

- 当選役は抽選表（フラグごとの成立役）から読みます。編集は抽選表側で行います。
- ボーナス持越し中の制御（例: `Replay_BB`）は、抽選フラグの「＋」でボーナス役を足します。
- 「複製」は選択中の制御を丸ごとコピーし、「名前 (1)」のように番号を付けます。右クリックで複製・削除。
- 「抽選表から一括作成」は、まだ無いフラグの制御をまとめて作ります。
- 内部名が `ReelControl.flagNames` に無いときは一覧に ⚠ が付きます（ベイクされません）。

中央は押し順タブごとに2つの表示を切り替えます。

- **滑り表**: 第一〜第三停止のリールごとに、押し位置（1〜21）・滑り・決め手を表示します。第二・第三停止は、先に止まったリールの停止位置を選んで見ます。
- **出目マップ**: 第一停止の止まり位置を選ぶと、縦 = 第二停止の押し位置、横 = 第三停止の押し位置で、出る出目を色分けします。マスを選ぶと3×3のプレビューが出て、「滑り表」でその条件の滑り表へ移れます。

決め手のラベル:

| ラベル | 意味 |
|---|---|
| `○○引込` | 当選役を揃えるための滑り |
| `○○狙い` | 狙う出目に寄せるための滑り |
| `回避` | 非成立役・出してはいけないリーチ目を避けるための滑り |
| `最短` | どの候補も同じなので、滑りが少ないもの |
| `手動` | Advanced で手動指定した滑り |
| `回避不能` | 最大滑りでは避けきれない押し位置 |

右側:

- **狙う出目**: 上ほど優先。小役の引込より先に効きます。右クリックで並べ替え・外す。リーチ目は②で「出てよい制御」にした制御でだけ追加できます。
- **この制御で出てよいリーチ目**: ②の設定の確認用です。
- **Advanced：滑り数の手動指定**: 「有効」にすると、滑り表の行をクリックして滑りを固定できます（「自動」で解除）。固定した位置も非成立入賞・リーチ目の漏れを毎回チェックし、問題があれば「手動指定による警告」に数えます。
- **結果**: 当選役・出目の割合と、チェック（非成立役の入賞・リーチ目の漏れ・手動指定による警告）。割合は全押し順・全押下位置を等確率で押したときの値です。

## ② 出目

停止後の3×3の形に名前を付けて登録します。

- マスを選び、パレットの図柄をクリックすると「含む → 否定 → 指定なし」の順に切り替わります。「含む」は複数指定でそのどれか、「否定」はその図柄以外。何も指定しないマスは ANY です。
- **押し順**: すべて／左・中・右第一停止のみ。選んだ押し順のときだけ、この出目を使います。それ以外の押し順では無いものとして扱います。
- **種類**: **基本目** はどの制御でも出てよい形。**リーチ目** は「出てよい制御」にチェックした制御でだけ出ます。それ以外の制御では、全押し順・全押し位置で出ないことを保証します。
- **出し方**: **通常** は停止位置を問いません。**特定停止位置のみ** は3リールそれぞれの停止コマ（下段の番号、複数可）を指定します。リーチ目ミッションの組み立てに使えます。
- **表示可否**: リーチ目は出てよい制御、基本目は狙っている制御ごとに、出せる経路数（✓）か出せない理由（✗）を表示します。

## 滑りの決め方

各押下位置で、0〜最大滑りの候補を次の順に比べ、1つに決めます。

1. **出してはいけないものを出さない。** 非成立役と、その制御で出てよくないリーチ目を、この後どう押されても避けきれる候補だけを残します。
2. **ボーナスを揃える。**「制御方式」がボーナス優先のときだけ、ここで引き込みます。
3. **狙う出目に寄せる。** 上の出目から順に、その出目になる割合が高い候補を選びます。
4. **小役を揃える。** 狙う出目で差がつかない押し位置で引き込みます。小役優先のときは、この後にボーナスを引き込みます。
5. **滑りが少ない候補。**
6. 手動指定した押し位置は、その値で上書きします。

各段では「この後の押し順・押下位置が等確率だとして、最善に滑らせたときに揃う（その出目になる）割合」が高い候補を選びます。

狙う出目のない制御は、当選役の引込だけで決まります。狙う出目を入れると、その分だけ小役の入賞率が下がることがあります（例: スイカAは右下がり、スイカBは上段に寄せると、それぞれの形の出方がはっきり分かれる代わりに、取りこぼしが増えることがある）。

同じ設計と機種データからは、いつも同じテーブルが生成されます。

## 今の制限

- 停止途中（第2停止時点のテンパイ形など）を条件にした指定はできません。
- 目押しの上手さや押し順の偏りは考慮しません。

## テスト

.NET SDK 8 があれば、Unityなしでエンジンを検証できます。

```
cd Packages/com.axtuki1.udonslot/Tests~/ReelRule
dotnet run -c Release
```

サンプル機種と実機（ASLOT-1）の配列で、非成立入賞0、引込率が総当たりで求めた最大値と一致すること、リーチ目が出てよい制御以外で出ないこと、ベイク後の配列を実機と同じ検索手順でたどった結果が生成結果と一致すること、などを確かめます。
