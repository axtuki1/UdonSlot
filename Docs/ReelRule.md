# ルール制御（試作）

フラグごとに「何を優先して止めるか」をテキストで書き、全押し順・全押下位置の滑りテーブルを自動生成する仕組みです。
セルを1つずつ編集する代わりに、数行のルールを書いて生成し、結果の一覧を見て直します。

- 画面: `UdonSlot > ルール制御`
- 生成エンジン: `Editor/ReelRule/Core`（Unityに依存しない純C#）
- テスト: `Tests~/ReelRule`
- 出力: 既存の `ReelControlData`（基本テーブル＋停止位置の条件付きテーブル）。実機側の処理は変更しません。

既存の「制御プロジェクト」「リール制御設計」などのツールとは独立しています。

## 使い方

1. 画面の「機種」に `ReelOutputController` を指定します。配列・有効ライン・成立役・抽選フラグはここから読みます。
2. 「ルールファイル」の「新規」でテキストファイルを作ります（既存の `.txt` を指定しても構いません）。
3. 「生成」を押すと、全フラグの結果が一覧に出ます。フラグを開くと、役ごと・停止形ごとの割合（押し順別）と、多い出目が見られます。
4. ルールファイルを直して、もう一度「生成」。これを繰り返します。
5. 納得したら「ベイク」。機種の `ReelControl` に登録された検索名と同じ名前のフラグを、対応する `ReelControlData` に書き込みます。その後シーンを保存します。

「レポート保存」は同じ結果を Markdown に書き出します。Codex などに状況を伝えるときに使えます。

## ルールを書かなくても動く

ルールファイルが空でも、抽選表の全フラグについて次の制御が生成されます。

- そのフラグの当選役を引き込む（ボーナス／小役の順は機種の「小役優先・ボーナス優先」設定に従う）
- 当選していない役は入賞させない（最後まで避けられる位置だけを候補にする）

ルールは、これに「この出目を狙う」「この出目は出さない」を足すために書きます。

## 書式

1行に1命令です。`#` から行末まではコメントです。インデントは見た目のためだけで、意味はありません。

```
最大滑り 4          # 省略時は機種の maxSlipCount
BET 3               # 有効ラインの判定に使うBET。省略時は3

# 停止形：上段・中段・下段の3行 × 左・中・右の3マス
停止形 右下がりスイカ
  スイカ *      *
  *      スイカ *
  *      *      スイカ

# 専用：狙う／許可したフラグ以外では出さない停止形（リーチ目など）
停止形 リーチ目A 専用
  *      *      *
  Seven  BAR    *
  *      *      *

フラグ WatermelonA
  狙う 右下がりスイカ

フラグ BB
  許可 リーチ目A

# GetReelControlFlagName をオーバーライドして検索名を増やしている場合
フラグ REPLAY_BB
  抽選 Replay        # 当選役を取り出す抽選フラグ
  成立 RedBigBonus   # 追加で当選扱いにする役（持越し中のボーナスなど）
```

### 停止形のマス

| 書き方 | 意味 |
|---|---|
| `*` | 何でもよい |
| `スイカ` | その図柄 |
| `CherryA\|CherryB` | どれか（OR） |
| `!Replay\|BellB` | それ以外 |

図柄名はリール配列（`ReelData.symbols`）の名前と完全一致です。空白を含む図柄名は使えません。

### フラグの中で書ける命令

| 命令 | 意味 |
|---|---|
| `引込 <役>` | その役を揃える。当選役だけ指定できる |
| `引込 なし` | 書いていない当選役を自動で引き込まない |
| `狙う <停止形>` | その停止形になりやすい位置で止める |
| `避ける <停止形>` | その停止形になりにくい位置で止める |
| `禁止 <停止形>` | その停止形は必ず出さない（非成立役と同じ扱い） |
| `許可 <停止形>` | 専用の停止形を、このフラグでは出してよい |
| `抽選 <フラグ>` | 当選役を取り出す抽選フラグ（省略時はフラグ名と同じ） |
| `成立 <役>` | 当選役を追加する |

英語の別名もあります: `shape exclusive flag lottery won pull prefer avoid deny allow maxslip bet`。

## 滑りの決め方

各押下位置で、0〜最大滑りの候補を次の順に比べ、1つに決めます。

1. **入賞させてはいけないものを避ける。** 非成立役・禁止停止形を、この後どう押されても避けきれる候補だけを残します。避けきれる候補が1つもない押下位置は「回避不能」として数えます。
2. **フラグに書いた行を上から順に比べる。** 前の行で差がつかないときだけ、次の行で比べます。
   - `引込`・`狙う` は「この後の押し順・押下位置が等確率だとして、最善に滑らせたときにその役（停止形）になる割合」が高い候補を選びます。揃う見込みがなくなった後は、今回のリール単体で役の図柄を有効ラインに出せる候補を優先します。
   - `避ける` はその割合が低い候補を選びます。
   - 書いていない当選役の引込は、書いた行の後ろに自動で付きます。役より停止形を優先したいときは `狙う` を先に、役を優先したいときは `引込 <役>` を先に書きます。
3. **滑りが少ない候補。**

同じルールと機種データからは、いつも同じテーブルが生成されます。

## 結果の見方

- **入賞率**: 全押し順・全押下位置を等確率で押したときの割合です。目押しの上手さは考慮しません。
- **非成立入賞**: 当選していない役が揃った、または禁止停止形が出た経路の数です。0でなければ、配列や最大滑りでは避けきれない組み合わせがあります。
- **回避不能**: 上の原因になった押下位置の数です。
- **出目**: 停止後の3×3の図柄と、その割合です。

## 今の制限（試作）

- 手動で特定の押下位置だけ滑りを変える「例外」はまだ書けません。
- 停止途中（第2停止時点のテンパイ形など）を条件にした指定はまだできません。
- 生成結果の滑り表を1マスずつ見る画面はありません（ベイク後は既存の画面で確認できます）。
- 目押しの上手さや押し順の偏りは考慮しません。

## テスト

.NET SDK 8 があれば、Unityなしでエンジンを検証できます。

```
cd Packages/com.axtuki1.udonslot/Tests~/ReelRule
dotnet run -c Release
```

サンプル機種で、全フラグの非成立入賞0、引込率が総当たりで求めた最大値と一致すること、ベイク後の配列を実機と同じ検索手順でたどった結果が生成結果と一致すること、などを確かめます。
