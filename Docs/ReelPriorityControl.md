# Reel Priority Control

`ReelOutputController.CalculatePrioritySlip`は、リール配列、有効ライン、配当表から滑りコマ数を自動算出します。

通常はInspector編集可能な`PayoutTable`を基底ReelOutputControllerへ設定します。ReelControlの明示テーブルを使用できない場合、基底が自動的にこの計算を呼び出します。`WinPair[]`と`int[][]`を直接渡すAPIは、機種固有コード内で配当表を組み立てたい場合の低レベルAPIです。

## ReelControlの検索用フラグ名

`ControllReel`は`GetReelControlFlagName()`の戻り値を`ReelControl.flagNames`から検索します。既定では`GetActiveFlag()`を返すため、既存の対応表をそのまま使用できます。

成立フラグとボーナス状態の組み合わせで制御を切り替える場合は、派生クラスで次のようにオーバーライドします（`bonusFlag`は派生クラスで保持する文字列です）。

```csharp
public override string GetReelControlFlagName()
{
    return GetActiveFlag() + "_" + bonusFlag;
}
```

戻り値と一致する名前（例: `REPLAY_BIG`）を`ReelControl.flagNames`に登録してください。この検索名はテーブル選択だけに使用し、成立フラグや自動滑り制御の抽選結果は変更しません。対応する制御データが見つからない場合は、従来どおり`DynamicControl`を使用します。

## 出目を見ながらテーブルを編集する

`ReelControlData`のInspectorで、以下の順に編集できます。

1. 「参照する機種」にリール配列を持つControllerを設定し、「停止順・今回の停止」を選びます。親にControllerがある場合は自動選択します。
2. 第2・第3停止では、「到達可能な停止形」から前段の出目を選びます。第1停止のテーブル出力、第2停止の条件付きテーブル出力を順にたどり、到達できる組み合わせだけを表示します。「この出目条件を作成」で、表示中のテーブルをコピーした条件テーブルができます。
3. 「候補計算の設定」で配当表、BET、最大滑り、優先方式、引き込む対象役を指定します。対象役は複数選択でき、未選択はハズレとして評価します。抽選表と成立フラグから対象役を選択した後、ボーナス役を追加することもできます。
4. 「推奨値をこのテーブル全体に反映」で初期値を作り、各押下位置の滑りを0〜4コマで調整します。行の位置番号を押すと、下部に各滑り候補の3リール出目、成立可能役、最大配当、対象外役の確定警告を表示します。
5. 「この停止順でテーブル制御」を有効にすると、保存した値を実行時に使用します。編集、条件作成・削除、一括反映はUndoに対応します。

第2・第3停止は「到達可能な未作成条件だけ推奨値で作成」でまとめて作成できます。同一の出目条件が登録済みなら値を維持し、到達不能な条件は生成しません。前段を編集して既存条件が到達不能になった場合、その条件の値は保持し、入力・推奨値の反映を無効にします。前段の変更後は到達可能性を再計算します。一括作成は1回のUndoで戻せます。

前段が自動制御の場合（全停止を自動制御する指定も含む）は、派生クラスが出力を変更できるため、そのリールの全停止位置を候補として残します。絞り込みはこのReelControlDataの有効な前段テーブルを基準にします。今回停止するリールは全位置で押下できるため、現在の押下位置の行は削減しません。プレビュー画像は元画像の縦横比を維持して表示します。

条件の位置番号は**滑り後の下段図柄インデックス**です。同じ図柄名が複数ある場合も区別します。「任意」にしたリールは絞り込みません。条件が重なる場合は、位置を指定したリール数が多い条件を優先し、同数なら先に登録した条件を使用します。

条件に該当しない場合は既存の基本テーブルを使用します。条件テーブルのセルを`-1`にすると、そのセルは基本テーブルへ戻ります。基本テーブルのセルも存在しない場合は従来どおり0コマです。テーブル制御が無効な停止順は`DynamicControl`を使用します。

候補計算には停止済みリールすべての具体的な出目が必要です。第2・第3停止の推奨値は、その出目に対応する条件テーブルへ反映します。任意条件のテーブルは手動編集できます。選択中テーブルと出目条件が異なる場合は、該当条件を開くか新規作成してから値を編集します。

候補計算は編集用の配当表評価です。非対象役の確定回避、役種別、役全体／今回のリールのみの引込可能性、配当・組合せ数、少ない滑りの順に比較します。未停止リールは配列上に必要図柄が存在するかを調べるため、後続テーブルで実際に入賞できることまでは保証しません。派生Controller独自の`DynamicControl`は呼び出しません。計算設定はInspectorの編集セッション内の補助設定で、保存される制御結果は滑り値です。

検索用フラグ名（例:`REPLAY_BIG`）と候補計算の対象役は独立しています。実行時の抽選状態やボーナス状態に合う対象役を指定してください。

## Priority Types

- `ReelRolePriority.SmallRoleFirst`: 小役優先。リプレイを含む非ボーナス役を先に引き込みます。
- `ReelRolePriority.BonusFirst`: ボーナス優先。ボーナス役を先に引き込みます。

- `ReelControlPriority.Payout`: 枚数優先。停止候補から成立可能な組み合わせのうち、最も高い配当を優先します。
- `ReelControlPriority.CombinationCount`: 個数優先。停止候補から成立可能な`WinPair × 有効ライン`の数を優先します。

最初に非当選役が確定しない停止候補を優先し、その中で役種別の優先を評価します。優先役種を引き込める停止候補が1つでもあれば、その候補を非優先役種より優先します。優先役種を引き込めない場合だけ、もう一方の役種へフォールバックします。

同じ役種別の候補内では、枚数または個数の主評価を行います。主評価が同じ場合はもう一方の評価値を比較し、それも同じ場合は滑りコマ数が少ない候補を選びます。

## Inputs

- `reelIndex`: 今回停止するリール。左から0、1、2です。
- `currentSymbol`: 滑り前に下段へ表示されている図柄インデックスです。
- `activePayLines`: 各リールの表示段を`0=上段`、`1=中段`、`2=下段`で表す配列です。
- `activeWinPairs`: 現在の抽選結果で入賞を許可する`WinPair`だけを格納した配当表です。
- `priority`: 枚数優先または個数優先です。
- `rolePriority`: 小役優先またはボーナス優先です。PayoutTable版の自動制御で使用します。
- `maxSlipCount`: 任意指定版で使用します。0〜4に制限されます。

`activeWinPairs`へ全役を無条件に渡すと、未当選役も引き込み候補になります。抽選結果に応じて許可された組み合わせだけを渡してください。重複当選では、許可する複数の`WinPair`を同じ配列へ入れます。

`PayoutTable`版では、`LotteryTable`で現在のフラグに登録された当選役だけを自動的に評価します。1つのフラグに複数の当選役がある場合は、そのすべてが候補になります。

## WinPair Rules

- `symbols`は左、中、右の順です。
- 図柄名は`ReelData.symbols`と完全一致で比較します。
- 空文字はANYとして扱います。
- `isReelStopOrderAny`がfalseの場合、`reelStopOrder`を左、中、右の停止順として照合します。
- 個数優先では、配当表の1要素を1つの図柄組み合わせとして数えます。異なる図柄組み合わせは別々の`WinPair`として登録してください。

## Calculation

0コマから最大4コマまでの各停止候補について、次を評価します。

1. 今回停止するリールの滑り後の下段図柄を求めます。
2. 既停止リールは、押下時の図柄と実際の滑りコマ数から最終停止図柄を求めます。
3. 未停止リールは、要求図柄がそのリール配列に存在するかを確認します。
4. 有効ラインごとに`WinPair`の図柄と停止順条件を照合します。
5. 今回の停止だけで確定する非当選役の数を求め、最も少ない候補を優先します。
6. 役全体を成立可能な候補があれば、その候補を優先します。
7. 停止済みリールで役全体を取りこぼしている場合は、今回のリール単体で当選図柄を表示できる候補へフォールバックします。
8. 配当の最大値と、成立可能な組み合わせ数を停止候補の評価値とします。

非当選役の確定判定では、既停止リールと今回停止するリールの図柄を照合し、未停止リールがすべてANYの場合だけ確定済みとみなします。たとえば`Cherry / ANY / ANY`は左リールにCherryを停止した時点で成立するため、Cherry非当選時はその停止位置を可能な範囲で避けます。一方、`Bell / Bell / Bell`は残りのリール停止で外せるため、左リール停止だけでは確定扱いにしません。

停止済みリールで当選役のラインを外した後も、残りのリールは自身に指定された当選図柄を最大滑りコマ数の範囲で引き込みます。たとえば中リールでスイカを取りこぼしても、右リールにスイカが指定されていれば右リール単体の引き込みを継続します。ANYが指定されたリールには引き込む対象図柄がないため、このフォールバックは行いません。

滑り候補と表示段の図柄インデックスは循環配列として扱います。既存のMainBoardとテーブル制御に合わせ、滑りコマ数は現在の下段インデックスから減算し、0番より前は配列末尾へ戻します。Udon上での動作差を避けるため、負数に対する剰余演算には依存しません。

## Example

```csharp
[SerializeField]
private WinPair[] activeWinPairs;

[SerializeField]
private ReelControlPriority priority = ReelControlPriority.Payout;

private int[][] activePayLines = new int[][]
{
    new int[] { 1, 1, 1 },
    new int[] { 0, 1, 2 },
    new int[] { 2, 1, 0 }
};

public override int DynamicControl(
    string[] symbols,
    int currentSymbol,
    int reelIndex,
    int stopReelCount)
{
    return CalculatePrioritySlip(
        reelIndex,
        currentSymbol,
        activePayLines,
        activeWinPairs,
        priority
    );
}
```

`symbols`と`stopReelCount`は既存の`DynamicControl`互換引数です。自動算出では`MainBoard`と`ReelData`から必要な状態を取得します。

`Runtime/<REV>/Example/BasicReelOutputController.cs` は、基底の標準自動滑りをそのまま使用する空のサンプル派生です。特殊な制御が必要な機種だけ`DynamicControl`をオーバーライドします。
